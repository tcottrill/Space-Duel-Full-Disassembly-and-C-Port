# AS2MSG (msgs.c) — translation notes

Module: message/text writer, ROM $7730-$7D04. Files: `msgs.c`, `msgs.h`,
`msgs_data.c` (generated by `tools/gen_msgs_data.py`). All routines below
execute in attract (per `tests/ref/coverage_attract.md`).

## Register protocols (derived from all call sites)

| routine | addr | in | out / effect |
|---|---|---|---|
| `AuxRoutineAddOffset` | $7730 | X = row 0-6; reads $D1 (language) | $D1==0: nothing. Else dark VCTR dx=Offset[4*X+$D1], dy=0. A,X,Y clobbered |
| `Mesgpos` | $7760 | A = dx, X = dy | JSRL word $AF61 (CPU $3EC2 message-origin stub) + dark VCTR A,X |
| `VectorGeneratorMessageProcessor` | $7770 | Y = message # | color $D6 (yellow) then message |
| `Brightness` | $7772 | X = color byte, Y = message # | TXA -> PassColor |
| `PassColor` | $7773 | A = color byte, Y = message # | TEMP2=Y; STAT $64/A; message |
| `VectorMessage5` | $7779 | Y = message # | TEMP2=Y; color $D2 (green); message |
| `VectorMessage7` | $777D | Y = color byte, **TEMP2 = message #** | STAT word, then VectorMessage6(TEMP2) |
| `VectorMessage6` | $7782 | Y = message #; reads $D1 | decodes + emits whole message, advances list ptr by total bytes |

## Y (list offset) tracking — the byte-exact pointer contract

VectorMessage2 writes glyph words at successive `(VGLIST),Y` offsets **without
advancing** the list pointer; Y accumulates 2 per character across the whole
message. Termination (either the $77CB stop-flag path or the code-0 purge
path) runs VectorMessage0: `DEY` then `AddY1ToVector` -> pointer += (Y-1)+1 =
exactly the bytes written. Modeled with `vg_poke_list(y,v)` /
`vg_advance_list(y-1)`; a message whose first code is 0 gives Y=0 -> DEY
wraps to $FF -> `vg_advance_list(0xFF)` adds $100 (lo unchanged, hi+1),
faithful to the 6502 carry.

## Packed text encoding ($77AC-$77CB)

Each byte pair B0,B1 = three 5-bit character codes + stop flag (5+5+5+1):

    char1 = B0[7:3]           A = B0>>2, AND #$3E in VectorMessage2
    char2 = B0[2:0]:B1[7:6]   ROL A / ROL TEMP2 / ROL A / LDA TEMP2 /
                              ROL A / ASL chain
    char3 = B1[5:1]           A = B1, AND #$3E
    B1[0] = 1 -> last pair    LSR TEMP2 / BCC loop

`AND #$3E` yields code*2 directly (the glyph-word table index). Code 0 =
early terminator. Codes 1-4 index $3248+2c (blank,'0','1','2'); codes >= 5
get +14 (`ADC #$0D`, carry set from `CMP #$0A`), skipping the '3'-'9' glyph
entries, so code 5='A', 6='B', ... (listing comment "10. FOR A, 12. FOR B"
refers to the pre-adjust A=2c). Upside-down messages (UPDOWN bit 7) use
$3456/$3457 instead of $3248/$3249. Note these bases are **2 below**
SaveCFlag's $324A/$3458, and VectorMessage2 does not advance the pointer, so
`vg_char()` is NOT used here — the glyph words are read straight from
`sd_vecrom[]`.

Carry quirk: the ROL chain's carry-in is UPDOWN bit 7 (left in C by
VectorMessage2's `ASL` at $77E9). Traced through the chain it only reaches a
discarded intermediate A — char2 is carry-independent. msgs.c implements the
chain literally, carry included.

## Message numbering and the two banks

`LanguageTablePointersSee` ($7803): 8 little-endian pointers = 4 languages x
2 banks, indexed X = lang*4 (+2 for bank 1):

| language ($D1) | bank 0 (Y=$00-$14) | bank 1 (Y>=$15, index Y-$15) |
|---|---|---|
| 0 English | $7813 | $78F4 |
| 1 German  | $7997 | $7AA0 |
| 2 French  | $7ACF | $7BC6 |
| 3 Spanish | $7BF4 | $7CD9 |

The split at `CPY #$15` ($7786): Y>=$15 sets carry, `ADC #$01` turns lang*4
into lang*4+2, and Y-$15 indexes the second bank's offset table. Each table
entry is the byte offset from the **table base** to the message's first
packed byte (`CLC / ADC (TEMP1),Y` at $779F, base kept in TEMP1/EACE =
$07/$08). Bank-0 tables have 21 entries; bank-1 sizes differ per language
(English 18, Spanish 4 — data-driven, no stored count). Data ends at $7D04
($7D05-$7FFF is $00 fill).

## Scratch RAM reproduced

- `TEMP1` $07 / `EACE` $08 — text pointer (final value = 1 past the
  message's last byte).
- `TEMP2` $0A — message number, then per-pair shift scratch; final value =
  last B1 >> 1.
- `g.ram[0xD1]` — language 0-3. This is `LANG`: the old RAM map put `LANG`
  at $DA, which is why this cell read as unnamed and the note here used to
  call it "distinct from LANG". Written by Gtoptn $7701, forced 0 = English
  by self-test $8A2A/$8AED. ($DA is `HSCORE`-3, the shift-down source slot.)

## Generated data

`tools/gen_msgs_data.py` extracts from the 64K image
(`../disasm/build/spacduel_64k.bin`, built by `disasm/gen_from_roms.py`):
`msgs_offset_rom[28]` ($7744, AuxRoutineAddOffset's Offset table, 7 rows x
4 languages) and `msgs_text_rom[0x502]` ($7803-$7D04). The generator
cross-checks every extracted byte against the listing's `.byte` lines —
result of the run: **1310/1310 bytes match** (covers both tables in full,
including Offset $7744-$775F, the pointer table $7803-$7812, and all four
languages' offset tables + packed text). Spot-checked by eye as well:
Offset row `$00,$F5,$F5,$F5,...` and pointers `$13,$78,$F4,$78,...` match
L7744/L7803.

## Externs

None. msgs.c uses only the shared headers: `vgutil.h` (`vg_add2`,
`vg_vctr_dark`, `set_vg_status`, `vg_poke_list`, `vg_advance_list`),
`sd_vecrom.h` (`sd_vecrom[]` glyph words), `sd_state.h`.

## Open questions

1. `g.ram[0xD1]` deserves a name (a `ZP_D1` macro in sd_state.h — orchestrator
   change); it is the display-language copy of the DIP language field.
2. `msg_rom()` returns 0 for addresses outside $7803-$7D04, where the 6502
   would read neighbouring program ROM. No caller can reach that with the
   ids used in attract/play (max Y observed $18-$26 region, all in range);
   a wild Y would diverge — acceptable until an oracle diff says otherwise.
3. The $3EC2 JSRL emitted by Mesgpos ($AF61) is assumed to be the shared
   message-origin stub seen in the frame-64 reference list (NOTES_oracle
   section 5); not yet decoded shape-by-shape.
